## Start here

Caimeo docs live in the same static website build as the product pages. The goal is to keep the landing pages focused while giving operators, builders, and reviewers somewhere concrete to go when they need commands, trust boundaries, and implementation details.

Use the project sections below when you already know what you are setting up. If you are evaluating the product suite, start with the public product pages and come back here for the operating details.

## Current docs coverage

- **Brainstack** has the deepest docs because it has installable client tooling, public skills, local capabilities, a Mac companion app, proposal curation, and tailnet workers.
- **Forseti** covers the action-governance shape: typed intents, decisions, approvals, execution release, and evidence bundles.
- **Tyche** covers deterministic scenario packs, comparison runs, scoring, replay bundles, and where simulation fits before production.
- **Valhalla** covers the planned delivery-room model, current status, and the boundaries that keep multi-agent work governed instead of open-ended.

> These pages are intentionally compact. They should explain the next command or next decision, not replace the repositories.
